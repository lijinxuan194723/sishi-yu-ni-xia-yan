更新于 2026-09-17。本文件区分已提交代码、已验证组件与完整产品，不以目录、测试宿主或原文保留代替功能迁移。

## 当前检查点

开发分支：`feature/v2.0.10-native-migration`。原生代码位于 `native/`；目标应用包名为 `cn.sishiyuni.nativeapp`。旧 React/Android 工程继续作为功能、数据及素材对照，不是原生模块的运行依赖。

本轮已核实的源码提交：`e820ee868ac5ec7bd1b0b8d64ce4371c151fb9f5`。其后本状态文档更新不改变受测生产代码。详细运行与失败边界见 `JOURNAL-DIALOG-VERIFICATION.md`；此前检查记录仍保留在原文件中。

## 本轮实际结果

| 检查 | 结果 |
|---|---|
| 原生journal/designsystem/测试宿主和测试APK编译 | 通过 |
| 核心JVM | 170项，0失败、0错误、0跳过 |
| Android API30 Room | 75项，0失败、0错误、0跳过 |
| Android API30 Compose | 79项，0失败、0错误、0跳过 |
| Android API35 Compose | 79项中77通过、2失败，0错误、0跳过 |

两系统使用相同界面用例；不将其当作158个不同功能覆盖点。新增手记和弹层用例全部通过。首轮改造引入的大字号表单保存按钮越界已修正，原断言与新增回归同时通过。

API35仍失败的是 `NavigationGlyphsUiTest.initialNightAndDialogReturnKeepActualSystemButtonsReadable` 和不含Compose的 `PlatformNavigationBaselineUiTest.plainAndroidWindowCanDisplayLightNavigationButtons`。二者都报告第一个导航按键区域没有足够亮色字形像素。配置标志正确、基线也失败，都不足以宣称应用已修好或简单归因于模拟器；仍须核对实际按钮位置、绘制和截图。失败项保持启用，没有降低断言或跳过测试。

## 边界

本轮未改旧React功能、图片素材、main或Release。完整手记列表写入被安全检查拦截后已停止该操作，没有换路径/编码绕过。独立编辑器、业务保护、通用弹层和测试已实际提交。

测试使用部分原生组件和真实Android内存数据库，不等于完整生产应用、真实用户数据迁移、磁盘掉电、系统结束进程或设备120Hz验收。关闭前保存和恢复草稿保护，不意味着尚未写入磁盘的瞬间输入能在断电后恢复。当前没有可替代2.0.9的完整原生APK。
