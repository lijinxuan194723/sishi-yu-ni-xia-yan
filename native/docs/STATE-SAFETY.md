# 原生业务状态与数据保护修订

本轮在 `feature/v2.0.10-native-migration` 中继续修改 Kotlin 业务代码。本文不表示 Compose 页面已经完成，也不表示原生 APK 可以替换旧版。

## 本轮修订

### 天气

`WeatherRepository` 保留原有 Http / DAO / PreferencesStore 构造入口，增加可注入 I/O 以测试真实协程取消与迟到响应。每次刷新绑定城市、坐标与请求序号；新请求取消前一次子任务，旧城市的迟到响应不能覆盖新城市。设置改变但未再次刷新时，也不会留下旧城市的加载状态。

本地缓存读取失败仍可联网。网络成功、写缓存失败时保留刚取得的天气，并单独报告缓存未保存，而不是退回旧数据。校验温度、风速、湿度、概率、日期及预报范围，过滤重复记录。未知天气代码不再自动画成雨。仍使用 Open-Meteo；没有复制 Xiaomi 客户端签名、替换天气服务或验证公共接口可用性。

### 会话与消息

标题、草稿、归档状态和活动时间分别更新，流式回复完成时只更新活动时间，避免读出旧会话对象再整体写回而覆盖新草稿。归档与会话切换受同一个回复门控制，不能向已归档会话直接发消息。

模型上下文采用预算内的连续末尾消息，不再跳过中间大消息后拼接更旧片段。数据库消息身份由 id、会话和序号共同约束；新消息用 ABORT 插入，已有消息以相同身份更新。同一会话序号冲突会明确失败，整个外层事务回滚，不能被当作成功保存。

### 学习计时与倒计时

`TimerTransitions` 集中处理纯状态转换。重复开始相同的运行中科目不重置时间；切换科目和覆盖暂停中学习都需要先结束原记录。暂停幂等并保留先前的分段。`reset("study", discardStudyConfirmed = true)` 只供明确确认丢弃后使用；默认重置不能删除未保存的学习。

`startCountdown(..., replaceExisting = true)` 只供用户明确确认替换后调用。普通调用不能覆盖已有运行中或暂停中的倒计时。数据库写入成功后才取消旧系统提醒，提前收到的到时事件重新安排，不能提前 1.5 秒结束。滑尺拒绝非有限数值，时间格式化和跨午夜拆分检查溢出。真实手机闹钟权限、后台杀进程、重启与通知仍需验收；最长学习时长沿用当前 24 小时限制。

### Skills

安装、更新与启用均按内容摘要校验。相同内容重装保留用户原启用选择；有变化的更新必须携带用户审阅时旧版本的 digest，更新后默认停用。技能已卸载或被其他操作更新后，迟到的安装／启用请求不能让它复活或启用未审阅内容。

原生管理界面接入 `install(candidate, expectedDigest)` 和 `setEnabled(id, true, expectedDigest)` 时，必须使用实际展示给用户并得到确认的摘要，不能后台读取新摘要替代用户确认。停用允许省略摘要。同一 ZIP 内重复路径、Unicode 等价路径或同名技能均拒绝，避免后一个覆盖前一个。此功能仍为指令技能，不执行 Shell/Python 等脚本。

### 自动长期记忆

移除原来每条消息 `take(1600)` 后仍推进整条归档位置的逻辑。现在按完整消息分批，并以 JSON 转义后的实际字符数计算请求预算，每批最多 24 条／60,000 字符。已静音、不完整回复等不送入提取器；遇到 streaming 消息停止，不能越过尚未结束的内容。连续多条用户消息不会因前 24 条内没有模型回答而卡住。

模型未返回非空字符串摘要和 facts 数组时不推进进度。提取期间原文改变则拒绝提交，并从未改变的检查点重试。指纹加入格式版本，使旧的截断式摘要自动失效并在后续整理中重建。每个工作任务继续最多执行三批，需要时继续排队，不要求手动点击整理。

单条历史消息本身若超过 60,000 个序列化字符，目前明确失败并保留原文和检查点，不假装已经处理；跨单条超大消息的断点分片尚未实现。以上保证的是代码路径和测试中的覆盖，不保证模型能保留每个语义细节，也不是端到端长期质量验收。
