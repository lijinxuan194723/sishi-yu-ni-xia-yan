版本名称仍为 2.0.10，Android versionCode 从 902060 增至 902061；修复批次 `hotfix.1-weather-timer`。基线为刚交付、此次重新上传的完整 `Four-Seasons-Luke-WebView-2.0.10-functional-source.zip`，SHA256 `faa30ee2ba95810a1806bce109ceeb5361cf3bc8823176819026a0cc1d29c7f5`。不是从旧 GitHub 分支重新拼出的版本，也没有更换为 Compose。

## 本次复现并修正的问题

### 天气布局
原温度容器写死105px高度，最大字号下数字盒超过容器且伸到天气描述行。插画又与文字共用重叠区域。现在温度改为自然高度，读数和插画分列，地点与两个44px操作按钮用独立网格；天气描述/单位、建议、更新时间各自在正常文档流内。日预报的高/低温分行，预报列随字号变宽，通过内部原生横向滚动保留完整七日内容。插画边缘单独柔化，避免新的矩形色块截断。

96组天气布局回归：320/360/393/430px宽 ×75%/95%/130%/160%字号 ×摄氏/华氏 ×-100/22/70摄氏的受控边界数据。长地点、温度、文本、插画、按钮、指标和七日内容的几何检查通过。边界天气是测试夹具，不是任何地点的真实天气。

### 按钮失效和页面横向偏移
首次没有科目时，旧“开始计时”直接disabled，看起来像无法点击。现在按钮可触摸，首次点击进入“选个科目，开始专注”；明确点击“添加并开始计时”才创建科目并开始，取消不产生记录。已有科目照常直接开始，数据未准备完成时仍保留读取保护。没有加入强制默认数学/英语，也不删除历史科目记录。

另复现了快速切换底栏后点击内部分区，浏览器对overflow:hidden的最外层滑页区域进行焦点滚动；它在Motion的translateX之外额外保留约110px scrollLeft，导致内容和按钮位置偏移。现在支持的WebView使用overflow:clip，旧引擎仅修正这个外层的额外滚动，绝不接管天气预报/文本/日期等内部滚动。按键、弹窗、拖尺保持各自的触摸交互。

48组计时触屏回归：四档宽度 ×568/640/820px高度 ×四档字号。每组先用elementFromPoint检查按钮中心和四个内部点，再实际tap开始、tap结束，不用force或DOM .click伪造交互。新用户取消/添加开始、提醒页开始暂停继续重置、重复完成不重复记账均有检查。

### 动画消失
旧指针由Motion为小SVG组自动生成transform-box:fill-box，并以100px/100px作为CSS原点；参考的是指针自身包围盒而非200×200表盘。在原APK资源回放约35秒时，针尖离表盘中心约0.966个直径，预期仅0.465，因此指针实际跑出了表盘。修复为显式SVG `rotate(angle 100 100)`，仍由Motion弹簧驱动，不增加每帧React重渲染。

36帧整圈/跨分/长时恢复样本，以及运行时真实中间帧均核对针尖与顶点半径。夏彦挂件的真实CSS变换也连续变化。保留系统减少动态效果和应用“季节动画”开关，时间本身不受动画启停影响。保留在DOM中的隐藏页面和内部分区暂停装饰，返回后恢复。没有通过强制开启动画覆盖用户的无障碍设置。
