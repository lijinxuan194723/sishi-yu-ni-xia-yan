# WebView 2.0.10 · 细节与稳定性修复 hotfix.2

本轮直接基于用户上传的 `Four-Seasons-Luke-WebView-2.0.10-hotfix1-source.zip`，SHA-256 `bd3b2ecc0b109c73737acd15f191d412ad6a1c08379c4899c44899477b787215`。不是回退到2.0.5重新拼接，也没有切换到Compose。版本名称仍为2.0.10，Android versionCode为902062；修复批次 `hotfix.2-detail-lifecycle`。

## 已复现并修正的问题

### 1. 拖尺被打断时误启动
旧版使用真实浏览器拖动后，模拟窗口失去焦点，再松手会启动倒计时；新代码将失焦、切后台、页面被隐藏、捕获丢失和第二触点视作取消，不视作确认。取消恢复拖动前数值，释放捕获并清理指针集合。新一轮正常拖动仍然松手即开始；键盘Home/方向键/回车继续有效。

指针结束事件可能发生在组件外，现在窗口级收尾在React处理正常释放之后执行。原来被输入框等排除的触点不再残留到下一次滑页，打断页面拖动后指示器回到当前页面。没有阻止内部文本选择、天气横向预报或普通纵向滚动，也没有把所有触摸事件改为强制阻止。

恢复或重新打开已有倒计时时，分钟输入和刻度从已保存时长初始化，而不是固定显示25分钟。实际剩余秒数不变。倒计时本身仍是应用内计时，锁屏/进程结束后的可靠响铃仍需使用现有系统时钟入口；本轮未增加后台闹钟权限。

### 2. 返回键被旧设置状态吞掉
从设置子页退出后打开“对话与技能”或Skills，Android返回桥原来会误把任何带settings样式的弹窗当作主设置页，先修改已经不在前台的设置状态，第一次返回没有关闭当前面板。现在只在真正打开的主设置子页中执行“返回索引”；其他弹窗关闭自身。检查了设置子页、索引、对话管理、Skills和保留输入草稿。

### 3. 天气更新、缓存日期和不完整数据
初次加载、手动刷新和自动检查统一遵守前台/联网条件。后台或离线不再继续发起刷新，断网取消在途请求；重新联网恢复同地点天气。切换地点后，旧请求即使延迟返回也不能覆盖新地点。

“今天/明天”按天气地点的日期与时区判断，不再无条件标注预报第一项为今天。跨日缓存的观测时间附完整日期；不把旧记录装成今日新数据。缺少湿度/风速/体感字段时不生成空白指标行，缺少逐日或小时数据时提供明确状态。

新增真实日期检查，过滤2月31日、重复/乱序预报、相互倒置的高低温和无法表示的时间戳。重复小时只保留一项并按时间排列；不为了填空编造值。无效新数据不会把之前有效的同地点缓存删掉。保留Open-Meteo单来源，没有引入其他模型天气或新的公共API。

### 4. 长聊天的历史列表
过去每个会话都重新扫描完整消息，复杂度是会话数×消息数，而且关闭的面板仍会运行这项整理。改成一次扫描后汇总，关闭时不扫描全量历史。9000条消息、300个会话的测试验证消息只被读取一次，原全局消息索引、草稿、归档状态和记忆原文引用不改写。

### 5. 备份恢复后的可编辑状态
修复首次读取失败后成功恢复备份，finally又把ready回写为false，导致恢复后仍只读的问题。恢复成功保持可编辑；恢复失败保留原可编辑状态与原数据。两份备份同时恢复会在第二次进入存储前拒绝，恢复期间也不接纳旧页面回调的保存请求。

这部分使用真实React和原useLocalData钩子、显式注入的存储适配器检查。验证的是钩子的状态与调用顺序，不等于已经实测IndexedDB事务、覆盖升级或手机断电恢复。底层durable-store、备份格式、记忆格式均保持字节不变。

## 必须保留的验证边界

本次生产CSS/JS在about:blank中回放，使用MemoryStorage和受控Android/网络桥。返回键检查调用实际产品返回桥函数，但未按过真机系统返回键。失焦/后台事件为模拟生命周期，正常拖动、点击、键盘是浏览器输入。原CSP本地HTTP访问被ERR_BLOCKED_BY_ADMINISTRATOR阻止，没有绕过策略，结果在environment/served-attempt.json。

没有连接Android设备；未完成实际安装、真实相册、软键盘、通知、API实时连通性、真正IndexedDB持久性、覆盖升级、断电、帧率或120Hz验收。构建仍保留大于500kB的JS分块提示，未隐藏，也不把构建大小换算成帧率。测试通过不等于任何设备上绝无问题。
